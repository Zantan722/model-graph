2026-09-14，在 macOS Apple Silicon 驗證。沒有發布新 Release。

## 實際 Codex 結果

僅送出 `tests/fixtures/thematic-repo` 的合成程式與文件，沒有使用使用者的其他專案。

| 圖種 | 視圖說明 | 本次選取 | 實際完成 | 產圖模型呼叫 |
|---|---:|---:|---:|---:|
| architecture | 3 | 1 | 1 | 1 |
| sequence | 6 | 1 | 1 | 1 |

兩次分析階段皆零次 PUML 產圖呼叫；未選項目保持 proposed，沒有 source。
架構總覽包含真實模組與 import／函式依賴，明確區分模組內記憶體資料與未知部署邊界。循序圖呈現查無使用者時的短路與回傳物件，没有假設 HTTP 路由。

第一次試跑發現一般架構提示錯誤帶入 C4 Container 層級，導致模組被壓成單一執行單元；停止該試跑，將一般架構與 C4 層級提示分離後重新驗證。此處數據是修正後結果。

實際輸出存於 `tests/fixtures/codex-selective-architecture.json` 與 `tests/fixtures/codex-selective-sequence.json`。`node tests/selective-live-report.test.cjs` 核對來源 SHA-256、精確引用片段、視圖類型、選取結果及 PUML 語法，不再呼叫模型。合成 repo 的驗證不代表任意生產 repo 的語意正確性。

## 介面與程式驗證

- Electron 實際打包 App：舊報告恢復、預設零選取、只送出所選兩個 ID、稍後補選一張、逐份同步、手動編輯保護皆通過。
- 1440、1024、768、600、375 寬度皆無水平溢出；另檢視 1440 與 375 的實際 renderer 截圖。
- 六圖種描述格式、C4 四層限制、錯圖種 metadata 偽裝、引用驗證、選取 ID 與 IPC 來源隔離、來源快照指紋、分批及失敗重試、取消保留、v1 報告相容與損壞檔保護皆通過。
- TypeScript、網頁／桌面 build、既有 PUML、graph、流程庫及來源容量回歸測試通過。Vinext 仍有原有的 route classification 提示。

本機安裝包：`release/0.5.0/Model-Graph-0.5.0-mac-arm64.dmg`。此輪沒有建立或驗證 Windows 0.5.0 安裝檔。仍使用 Model Graph 的 SVG／PUML 引擎，參考 Archify 的圖種分工、清楚視圖目的及來源核對原則，沒有移植其 renderer 或宣稱通過 Archify showcase 檢查。
