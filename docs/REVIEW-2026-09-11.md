## 安全邊界與剩餘風險

- Electron 使用 sandbox、contextIsolation，停用 renderer Node.js；没有暴露任意 IPC 或 shell API。
- `modelgraph://app/` 僅能讀取 renderer 的 index.html 與符合白名單的 assets；路徑穿越、其他 origin、非資源檔案被拒絕。CSP 限制遠端腳本與連線，視窗導向／彈窗與權限請求被拒絕。
- PUML include 只辨識少數已知 C4 引用；不執行巨集、shell，也不讀取 URL 或任意本機檔案。UI 以 React 文字呈現來源內容。
- 套件掃描：修補前 24 個受影響套件（1 Critical、14 High、8 Moderate、1 Low），修補後剩 4 Moderate、0 Critical／High。這是受影響套件數，並非四個獨立可利用漏洞。
- 剩餘：`drizzle-kit → @esbuild-kit/esm-loader → @esbuild-kit/core-utils → esbuild`。目前未啟用資料庫功能；舊 esbuild 開發伺服器有已知風險。npm 的自動修法會把 drizzle-kit 降到不相容的舊版，因此未使用 `--force`。該鏈未打包進桌面 App。正式分享開發環境前可移除未用的資料庫 scaffold，或升級至已修補且測試相容的工具。
- macOS 安裝包仍未簽署／公證；沒有自動更新。Windows／Linux 僅有打包設定，尚未實機驗證。
- localStorage 不等同文件系統備份；清除 App 資料、裝置損壞、強制終止或多個網頁分頁同時編輯仍有遺失／互相覆寫風險。桌面版有單實例限制，瀏覽器分頁尚無衝突協調。
- PUML 是子集轉換器，並非完整 AST／原生 PlantUML 引擎；alt／loop／巢狀邊界與原始樣式仍不能完整往返。工作流程匯出為 state 圖語法，此點已在介面與 README 說明。

## 驗證

- `node tests/audit.test.mjs`：異常 metadata、座標／註解限制、診斷上限、JSON 白名單、單張損壞不影響其他圖、原文不覆寫、備份失敗。

- `npx tsc --noEmit`、網頁 production build、Electron renderer build。
- Electron smoke test：真實 renderer、六個圖表類型、PUML 視窗、實際匯出檔案、localStorage、安全 origin、Node 隔離，以及實際滑鼠拖拉→復原→點選後重做仍存在。
- npm audit 結果保留為 `docs/dependency-audit-summary.json`，不包含本機目錄或憑證。

## 建議後續順序

1. **文件保存與救援**：新增「開啟專案／另存新檔」與包含全部畫布的專案格式；桌面以原子檔案寫入、自動備份與版本快照為主，localStorage 只存偏好。這比增加 AI 功能更能保護實際工作。
2. **以 PUML 原始碼為核心**：引入 AST／保留原文區塊的編輯方式，支援團隊實際使用的 C4 boundary、sequence alt／loop、自訂 include。不能修改的結構保留唯讀與原生預覽；避免「轉換成功但語義改變」。
3. **發行流程**：Developer ID／公證、版本更新策略、Mac／Windows CI 建置與操作測試，再提供公開下載。不要把個人簽署憑證放進 Git。
4. **編輯器效能與維護**：拆分目前集中的 page.tsx 為 Canvas、Inspector、History、Persistence hooks；快取 id→node 索引及 edge 幾何；用 requestAnimationFrame 更新拖拉，批次合併文字修改的 undo；擴充鍵盤快捷鍵。
5. **操作品質**：吸附對齊、自動排版、框選／多選、複製貼上、跨層 C4 導覽、明確的文件名稱與未保存狀態。這些是尚未實作的功能，不應描述成已支援。
